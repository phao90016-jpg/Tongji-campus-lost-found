## 正文

```markdown
## 一句话描述

把"丢了东西在群里刷屏、捡到东西没处交"变成一条可核验的流程：拾取者登记、失主检索、
认领申请、双人审核、交接核销，每一步都留痕，冒领会被拦在交接之前。

## 要解决的问题

1. 失物信息散在班级群、校园墙、保卫处登记簿里，三小时就被刷走，失主找不回；
2. 认领无法核验——拾取者只能在群里问"说说是什么颜色"，谁说得像就给谁，真失主反而放弃；
3. 为了让人联系，失主把手机号、学号甚至证件照发在群里，撤不回来。

## 目标用户

主要：失主（在校学生）、拾取者（学生 / 后勤人员）、保卫处失物招领处管理员。
次要：系统管理员（课程项目内由团队兼任）。

## 角色（≥3）

- 学生（失主 / 浏览者）`student`
- 拾取者 `finder`（需实名认证，角色可叠加）
- 审核员（保卫处 / 失物招领处）`reviewer`
- 系统管理员 `admin`
- 定时任务 `system`（系统角色，自动过期 / 超时升级 / 通知补扫）

## 外部集成点（≥1）

- 学校统一身份认证（OAuth2 授权码 / CAS）——唯一实名来源
- 对象存储（MinIO / OSS）——图片存取，预签名 URL
- 微信服务号模板消息 / 企业微信应用消息——认领结果通知
- 邮件 SMTP——通知兜底通道
- 内容安全 API（v0.3 可选）——敏感词与违规图片
- 校园卡系统（v0.3 可选）——挂失状态校验

## 三个可交付增量

- v0.1（迭代 1）发布 → 检索 → 申请认领 → 审核 → 交接核销
- v0.2（迭代 2）举报与信用分、通知与降级投递、统计看板、权限与审计
- v0.3 相似物品推荐、关键词订阅、报表导出、OCR 证件打码、开放只读 API

## 规模自检

|---|---|---|
| 可交付增量 | ≥3 | 3（前两个为题目给定的两轮迭代） |
| 用例 | ≥20（含 ≥2 非功能） | 39（35 功能 + 4 非功能） |
| 分析类 | ≥15 | 29 |
| 技术风险点 | ≥1 | R1 冒领、R2 敏感信息泄露、R3 并发冲突 |
| 用户角色 | ≥3 | 4 类角色 + 1 系统角色 |
| 外部集成点 | ≥1 | 6 |

## 为什么不是单表 CRUD

认领必须能核验（核验问题 + 双人审核 + 交接码）、状态必须能流转（两条状态机 + 并发互斥）、
信息必须能分级（字段脱敏 + 图片遮蔽）、行为必须能追责（举报 + 信用分 + 申诉 + 审计）。
四处都能造出可断言的测试用例。

## 范围收敛说明

二手交易、快递代取、跨校流转、站内即时聊天、自建密码体系、AI 自动判定认领真伪均移出本期，
理由与替代方案见 `docs/00-立项/选题文稿.md` 第五节。

## 技术栈

Vue 3 + TypeScript + Vite ／ FastAPI（Python 3.11+）／ 开发 SQLite（FTS5）、部署 PostgreSQL ／
对象存储 MinIO ／ GitHub Actions 做 CI。
```
