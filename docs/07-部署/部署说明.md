## 1. 环境要求

| 项 | 版本 | 说明 |
|---|---|---|
| 操作系统 | Linux（Ubuntu 22.04+）；开发可用 Windows / macOS | |
| Python | 3.11+ | 后端 |
| Node.js | 20+ | 前端构建 |
| 数据库 | 开发 SQLite 3.24+（需 FTS5）；部署 PostgreSQL 15+ | 部分唯一索引与 FTS5 已在 `probe/` 验证 |
| 对象存储 | 开发本地磁盘；部署 MinIO 或云 OSS | 需支持预签名 URL |
| 反向代理 | Nginx 1.24+ | 静态资源 + `/api` 反代 |

## 2. 本地启动（骨架期即可用）

```bash
# 后端
cd src/backend
python -m venv .venv
source .venv/bin/activate            # Windows: .venv\Scripts\activate
pip install -r requirements-dev.txt
cp .env.example .env                 # 填配置；.env 不提交
pytest -q                            # 应全绿
uvicorn app.main:app --reload        # http://localhost:8000/health

# 前端
cd src/frontend
npm install
npm run dev                          # http://localhost:5173，/api 代理到 8000
```

## 3. 生产部署

> v0.1 补齐。至少包含以下五项，缺一项不算部署完成。

| 项 | 做法 |
|---|---|
| 反向代理 | Nginx 托管前端静态文件，`/api` 反代到 `127.0.0.1:8000`；开启 gzip 与 30 天静态缓存 |
| 进程守护 | systemd unit `campus-lost-found.service`，`Restart=always`，`EnvironmentFile=/etc/clf/.env` |
| 环境变量注入 | 密钥放 `/etc/clf/.env`（权限 600），不写进 unit 文件，不进镜像 |
| 数据库迁移 | `migrations/*.sql` 按序号执行，执行前 `schema_version` 校验；回滚脚本同 PR 提交 |
| 健康检查 | 外部探针 `GET /health` 每 30s 一次；连续 3 次失败告警 |

## 4. CI/CD

| 环节 | 实现 |
|---|---|
| 持续集成 | `.github/workflows/ci.yml`：后端 `ruff check .` + `pytest -q`；文档 `check_links.py`；红灯禁止合并 |
| 持续部署 | 待 v0.1 配置（GitHub Actions → 服务器 SSH，或 Pages / Vercel 托管前端） |
| 发布 | 每个增量打 Release `v0.1` / `v0.2` / `v0.3`，Release 说明里附测试报告链接 |

## 5. 健康检查与监控

| 项 | 实现 |
|---|---|
| 存活探针 | `GET /health` → `{"status":"ok"}` |
| 就绪探针 | `GET /api/v1/meta`（v0.1 起需数据库可读） |
| 审核队列积压 | 工作台超时条数；>10 条标黄，>30 条告警 |
| 通知投递失败 | `delivery` 表 `failed` 数；连续 10 条告警（R4） |
| 存储失败 | `item_image.status='pending'` 比例；>5% 告警（R6） |

## 7. 回滚方案

> v0.1 补齐。

| 场景 | 动作 |
|---|---|
| 新版本接口报错 | 回滚代码到上一个 Release tag，重启服务 |
| 迁移脚本出错 | 执行对应 `down` 脚本，校验 `schema_version` |
| 数据损坏 | 从最近一次备份恢复（备份策略：每日全量 + WAL 归档） |
| 外部通道不可用 | 切 `NOTIFY_PROVIDER=console`，站内消息仍可用，业务不中断 |

## 8. 已知限制

- 单实例部署，调度与 API 同进程；多实例需把调度拆出并加分布式锁（不在本期）
- SQLite 单写锁，压测并发写需切 PostgreSQL
- 微信模板消息需用户先关注服务号，未关注时只走站内与邮件
