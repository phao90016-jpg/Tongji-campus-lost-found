# 演示脚本

> 交付物⑧｜对应单元：8 交付演示｜检查点：期末答辩
> 负责人：项目经理（主讲）+ 全组（分工）｜状态：**初稿**，v0.1 可运行后按实际界面修订

> 答辩形式：每组 20 分钟 = **演示 12 分钟** + 问答 8 分钟（每人至少答一问）。
> 要求覆盖**功能**与**非功能**各一项以上，且必须**现场可运行**。

- [ ] 通知通道开关确认：先演示"微信开"，再切"关"演示降级
- [ ] 备用方案：录屏 + 截图 + 数据库备份文件

## 3. 演示 1：发布 → 检索 → 申请（功能）

**目标**：证明"招领必须带核验问题，失主能被检索到并提交申请"。

1. 用王同学（拾取者）登录 → 点「发布招领」
2. 填：标题"图书馆三楼捡到校园卡一张"、分类"证件卡类"、地点"图书馆 3F"、拾取时间
3. 设置核验问题："卡套是什么颜色？" → 答案"透明蓝色"
4. 上传一张校园卡照片 → 提示"已生成遮蔽图，原图仅审核员可见"
5. 提交 → 状态"公示中"
6. 切到李同学（失主）登录 → 首页搜索"校园卡" → 结果出现该条（**展示遮蔽图，不是原图**）
7. 点进详情 → 点「申请认领」→ 系统展示核验问题 → 答"透明蓝色"→ 填理由 → 提交
8. 页面显示"待初审"

**要讲的一句话**：「拾取者不用公开手机号，失主也不用在群里自证——核验问题把'谁说得像'变成'谁答得出'。」

## 4. 演示 2：初审 → 终审 → 交接（功能）

**目标**：证明初审给建议、终审给结论、获准领取人验物并确认的流程。

1. 切王同学 → 「待初审」看到申请，答案显示"透明蓝色 ✓ 与预留答案一致"
2. 点「建议通过」→ 状态"待终审"（**注意：初审只是建议**）
3. 切张老师（审核员）→ 工作台 → 待终审 1 条 → 打开
4. 展示：遮蔽图 / 原图入口、申请人历史（申请 1 次、信用分 100）、初审意见
5. 点「通过」→ 申请详情展示「已通过，待领取」及领取安排
6. 现场：李同学验物并收到后，在申请详情点「确认已领取」
7. 页面显示"交接完成"，招领状态"已交接"
8. 重试确认 → 返回同一确认人和时间。切换到保管方账号，无法代点确认

**要讲的一句话**：「初审由拾取者做，终审由保卫处做——两个人各有各的信息，一个人说了不算。」

## 5. 演示 3：冒领拦截 + 越权 403（非功能）

**目标**：证明权限与互斥是硬的，不是只藏了按钮。

**冒领拦截**

1. 用第三个账号（或赵同学）对同一条招领提交申请
2. 系统返回"该物品已有认领在审核中"（409 `CLAIM_CONFLICT`）
3. 展示数据库/日志：该物品进行中申请数 = 1

**越权拦截**

1. 用李同学记下自己申请的 ID（地址栏可见）
2. 退出，用赵同学登录，直接在地址栏访问该 ID
3. 页面返回 403，不显示任何内容；**不区分"不存在"与"无权限"**

**脱敏**

4. 打开 Network，展示响应里手机号是 `138****8000`，不是明文
5. 用审核员账号打开同一接口，展示明文 + 审计日志多一条 `pii.read`

**要讲的一句话**：「前端藏按钮不算权限控制，后端按归属校验才算；手机号在序列化层就脱敏了，抓包也拿不到。」

## 6. 演示 4：举报处置 + 通知降级（v0.2）

**目标**：证明系统"跑一个学期不出事"。

**举报处置**

1. 李同学举报一条明显虚假的招领（类型：虚假信息）→ 填说明
2. 张老师 → 举报队列 → 处置「下架 + 警告」
3. 展示该用户信用分 100 → 90；招领状态转"已关闭"
4. 展示被处置人可申诉（点开申诉入口）

**通知降级**

5. 张老师把通知通道切成"仅站内"（或停掉微信凭据）
6. 提交一条新的认领申请 → 观察投递记录：微信 `failed` → 邮件/站内 `sent`
7. 打开"投递记录"，展示每次尝试的通道、耗时、结果码
8. 重启后端进程 → 展示未发送任务被补扫，且不重复发送

**要讲的一句话**：「通知不是'发过就算'——站内消息写入后可查，通道失败会降级，每次尝试都有记录。」

## 7. 演示 5：看板与追溯（管理面）

1. 打开统计看板：发布量、认领成功率、平均处理时长、分类分布、地点 Top10、超时率
2. 点"平均处理时长"的数字 → 下钻到申请列表，条数与口径一致
3. 打开 `docs/02-需求规约/需求追溯矩阵.md`：随机指一条需求 → 用例 → 分析类 → 设计条目 → 测试用例
4. 打开 `.github/workflows/ci.yml` 与 Actions 页面：展示红灯禁合并

**要讲的一句话**：「每个数字都能点开看明细，每条需求都能追到测试用例——文档链不是写给人看的，是能核对的。」

## 8. 收尾：过程留痕（1 分钟）

依次展示：

1. **Issues** —— 需求与缺陷的闭环情况

3. **Actions** —— CI 绿灯率

## 10. 风险与预案

| 风险 | 预案 |
|---|---|
| 现场网络不通 | 切本地演示机；备好录屏 |
| 统一认证不可用 | 用本地兜底账号登录（提前登录好备用会话） |
| 数据库损坏 | 替换备份文件（答辩前 30 分钟做一次快照） |
| 超时 | 砍掉演示 5，优先保功能与非功能演示 |
| 被点名讲不清自己负责的部分 | 每人提前对着自己的 PR 讲一遍 |
