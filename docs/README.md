## 3. 文档链可追溯要求

设计条目要能指回需求条目，测试用例要能指回需求与设计。追溯关系统一维护在
[02-需求规约/需求追溯矩阵.md](02-需求规约/需求追溯矩阵.md)，每个增量发布前跑一次覆盖率自查。

| 链路 | 要求 |
|---|---|
| 需求 → 用例 | 27/27 覆盖（已完成） |
| 用例 → 测试 | 每个 UC 至少 1 条 TC（第 7 次课后补齐） |
| 设计 → 需求 | 每个 DES 至少指回 1 条 REQ |
| 模型 → 需求 | 每张图标注对应 UC / AC 编号 |

## 4. 写作约定

- 每个文档首部写清：对应单元、检查点、负责人、状态（草稿 / 预研 / 待评审 / 已评审 / 基线）
- 评审必须留"缺陷清单"，不允许只写"都同意"
- 图表以源文件存放在 `models/`，渲染图放 `docs/assets/`，文档用相对路径引用 `../assets/xxx.png`
- 一图一 PR；改了 `.puml` 要同步重渲染并替换图，避免图文不一致
- 待填写项必须写清"缺什么、由谁补、什么时候补"，不允许只写"待填"
- **诚实原则**：没有实测的数据写"待测"并给出测法；外部接口没授权就写"未实测"
