## 业务处理

下面按一次认领从发布到结束的顺序说明业务。每一步都写清操作人、系统检查、成功结果和常见失败。

### 1. 拾取者发布招领

拾取者填写物品信息、交接地点和 1 至 3 个核验问题，并为每个问题填写答案。

系统检查必填项和图片格式。校验通过后，发布进入 `published` 状态，可以被检索和申请。

图片上传失败时，文字内容仍然发布，图片标为待重传。缺少核验问题时，发布失败。

### 2. 失主提交认领

失主查看招领详情，填写认领理由、核验答案和可选材料。普通详情只显示问题，不显示招领方预留的答案。

系统在同一个事务中检查以下条件：

- 招领仍可申请。
- 申请账号不是发布人。
- 该招领没有进行中的申请。
- 当前账号没有该招领的进行中申请。

检查通过后生成 `pending_first` 申请，物品继续处于 `published`，但该申请已占用认领名额。已有名额时返回 `409 CLAIM_CONFLICT`。

### 3. 拾取者初审

拾取者查看申请理由、核验答案和材料，选择“建议通过”或“建议驳回”，并填写理由。

两种建议都只表示拾取者的判断。提交后申请进入 `pending_final`，不会直接改变物品状态。

初审只能提交一次。非发布人或无关人员不能提交初审。

### 4. 审核员终审

审核员查看申请人提交的材料、答案和拾取者初审意见，选择通过或驳回。

提交前，系统确认审核员不是该申请的申请人或发布人。审核通过时，申请变为 `approved`，物品变为 `claiming`。审核驳回时，申请变为 `rejected`，认领名额释放。

终审只处理当前申请。旧页面重复提交时返回 `409`，不得覆盖已经写入的结论。

### 5. 领取人确认领取

终审通过后，只有获准领取人可以执行领取确认。领取人应在线下核对并收到物品后操作。

首次确认成功后，系统写入一条领取确认记录，申请变为 `completed`，物品变为 `handed_over`。

同一领取人重复确认时，返回原确认记录，不重复写状态日志或通知。

### 6. 撤回、编辑和关闭

申请人在 `pending_first` 或 `pending_final` 状态可以撤回。撤回后申请结束，认领名额释放，原记录保留。

从认领申请提交成功开始，发布人不能修改核验问题、答案和物品图片。存在进行中申请时，也不能直接关闭发布。

没有进行中申请时，发布人可以编辑未认领部分或关闭发布。已交接的发布不再接收申请。

## 始终成立的约束

上面这些步骤之外，系统还要一直满足以下条件：

| 约束 | 说明 |
|---|---|
| 单一进行中申请 | 同一招领最多有一条 `pending_first`、`pending_final` 或 `approved` 申请 |
| 字段可见性 | 普通用户看不到核验答案；手机号默认脱敏；原图只向授权人员开放 |
| 审计 | 终审、领取确认、角色变更和明文读取写审计日志 |
| 通知隔离 | 站内消息写入后即可查看；外部通知失败不回滚审核或领取结果 |

## 非功能需求

| 编号 | 目标 |
|---|---|
| N-01 | 1 万条发布数据下，检索接口 P95 不超过 800ms |
| N-02 | 同一招领 10 个并发认领请求，只有 1 个成功 |
| N-03 | 非授权请求返回 403，响应体不包含受保护字段 |
| N-04 | 图片上传失败不阻塞文字发布，用户可重试 |
| N-05 | 生产环境不保存明文密码、密钥或真实个人测试数据 |

性能指标是目标值。当前探测脚本只验证了 SQLite 查询和唯一索引，业务接口尚未实现，不能引用为系统实测结果。

## 验收场景

| 编号 | 操作 | 通过条件 |
|---|---|---|
| A-01 | 拾取者发布招领并设置核验问题 | 招领进入可检索状态，问题存在，答案不出现在普通详情 |
| A-02 | 失主提交认领 | 生成待初审申请，拾取者能收到站内消息 |
| A-03 | 第二个账号并发提交同一物品 | 只有一条申请成功，其余返回 `409 CLAIM_CONFLICT` |
| A-04 | 拾取者提交初审建议 | 状态进入待终审，记录建议和理由 |
| A-05 | 申请人尝试终审自己的申请 | 返回 403，不产生终审记录 |
| A-06 | 审核员终审通过 | 申请待领取，物品认领中，领取安排可查看 |
| A-07 | 非获准账号确认领取 | 返回 403，状态不变 |
| A-08 | 获准领取人重复确认 | 返回同一确认记录，不重复写状态日志 |
| A-09 | 学生请求他人受保护字段 | 手机号脱敏，隐藏字段不进入响应 |
| A-10 | 图片上传失败 | 文字发布成功，图片状态为待重传 |

## 明确不做

- 不显示核验答案给普通浏览者。
- 不自动批准认领。
- 不允许同一物品存在两条进行中申请。
- 不把“通知已发送”视为“用户已知情”。
- 不把领取人确认当作线下交付的独立证明。
