## 1. 规则

| 编号 | 规则 | 具体要求 | 违反的处理 |
|---|---|---|---|
| RULE-01 | 时长 | **每次课 8 分钟主讲**（7 分 30 秒处给 30 秒提示，8 分 30 秒强制结束），另留 2 分钟提问 | 超时当场打断，未讲完的部分不计入 |
| RULE-02 | 人人主讲 | **每人至少主讲 1 次**；6 个讲解位由 5 人分担，允许 1 人讲 2 次 | 未主讲者该单元过程分扣减 |
| RULE-03 | 内容必须有留痕 | 讲的每个结论都要能指到仓库里的文件（文档、ADR、PR、测试输出、评审单）。**没有留痕的内容不许讲** | 现场抽查，指不出来即视为"口头内容"，不计分 |
| RULE-04 | 结构固定 | 一句话结论 → 本次交付了什么（链文件）→ 关键决策与理由（3 条）→ 已知问题与下一步 | 结构缺失的讲稿退回重写 |
| RULE-05 | 表格要求 | 讲稿至少含 1 张表格（对比、缺陷清单、指标任选），不接受纯散文 | 同上 |
| RULE-06 | 追问准备 | 讲稿末尾必须写"如果老师追问 X，回答 Y"，**至少 3 组**，且问题要是真会被问的 | 同上 |
| RULE-07 | 讲稿归档 | 讲前 1 天提 PR 到 `docs/10-课堂讲解/`，讲后 24 小时内补"实际用时 / 被追问的问题 / 答得不好的地方" | 未归档视为未讲 |
| RULE-08 | 不许念 PPT | 允许看提纲，不允许逐字念稿；数字必须说得出出处 | 现场提醒，第二次扣分 |
| RULE-09 | 与 PR 挂钩 | 主讲人本单元的 PR 数不少于 2 个（章程要求每人 ≥10 个被合并 PR，分摊到各单元） | 与过程分挂钩 |

> 关于 RULE-02 的说明：8 次课只有 6 个讲解位，是因为第 1 次课用于教师讲规则与组内分工、第 7 次课是设计定稿评审会（由评审组织人主持，全员参与，不占讲解位）。这不是"少讲一次"，而是把第 7 次课换成了更高强度的集体输出。

## 4. 讲稿存放约定

| 项 | 约定 |
|---|---|
| 目录 | `docs/10-课堂讲解/`，不建子目录（8 份讲稿平铺，便于扫） |
| 命名 | `讲稿-第N次-<主题>.md`，如 `讲稿-第3次-需求规约.md`；N 用阿拉伯数字，主题用 2–6 个汉字 |
| 首部 | 每份讲稿第一行下方必须有 `> 主讲人：…｜课次：…｜状态：…` 三要素 |
| 结构 | 固定六节：§1 一句话结论 / §2 本次交付了什么 / §3 关键决策与理由 / §4 已知问题与下一步 / §5 追问准备 / §6 讲后记录 |
| 篇幅 | 正文 900–1200 字（不含表格），按每分钟 120–150 字估算，留出停顿与看表格的时间 |
| 提交流程 | 讲前 1 天提 PR → 至少 1 人 review（优先评审组织人，查"是否每条都能指到文件"）→ 合并 |
| 讲后补记 | 24 小时内在 §6 补：实际用时、老师追问的 3 个问题、哪个回答最差、下次怎么改。**这一节比讲稿本身更能说明成长** |
| 版本 | 讲稿修改直接改同一文件，不建 v2；§6 只追加不删 |
| 关联 | 讲稿里出现的每个结论都要有相对路径链接；链接失效视为讲稿不合格 |

## 5. 自评清单

> 每次讲完当天填，勾不上的一项就是下次要改的地方。全组共用同一份清单，便于横向对比。

**讲前**

- [ ] 讲稿已按 §1 的六节结构写完，正文 900–1200 字
- [ ] 至少 1 张表格（对比 / 缺陷清单 / 指标任选）
- [ ] 至少 3 个仓库相对路径链接，且链接可点开
- [ ] 至少 3 组"如果老师追问 X，回答 Y"，且 X 是真会被问的
- [ ] 已按 8 分钟试讲 1 遍，实际用时 ≤8 分钟
- [ ] 关键数字都有出处（台账编号 / 缺陷编号 / 测试用例编号），不是"大概"

**讲中**

- [ ] 前 30 秒说出了"一句话结论"，没有铺垫背景
- [ ] 没有逐字念稿，没有长时间背对听众看屏幕
- [ ] 主动说出了 1 个"我们做错的地方"（评审缺陷 / 弃用的 AI 产出 / 返工）
- [ ] 留了 2 分钟提问，且没有用"这个我们后面会做"糊弄过去

**讲后**

- [ ] 24 小时内在 §6 补了"实际用时 / 被追问的问题 / 答得最差的一处"
- [ ] 被追问但没答上的问题，已建 Issue 或补进文档
- [ ] 讲稿 PR 已合并，链接无失效
- [ ] 本单元 PR 数 ≥2（与 RULE-09 对齐）
