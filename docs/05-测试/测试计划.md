# 测试计划

> 对应单元：7 测试｜检查点：第 7 次课起（第 15 周）
> 负责人：测试 / 质量工程师｜状态：**模板**，随 v0.1 编码推进填写
> 依据：[SRS v1.0](../02-需求规约/SRS-v1.0.md)、[需求追溯矩阵](../02-需求规约/需求追溯矩阵.md)

> 本文件在第 11 周只定结构与口径。**测试执行数据必须来自真实运行**，不允许预估填写。

## 1. 测试目标

验证系统满足 SRS v1.0 的功能与非功能需求。重点覆盖四条最容易出错的路径：

1. **并发互斥**（REQ-N-002）：同一招领的 N 条并发申请只允许 1 条进入待终审；
2. **脱敏与越权**（REQ-N-003）：非授权角色读不到明文手机号，越权 403 且不泄露资源存在性；
3. **状态机**（REQ-F-019）：非法迁移一律 409，且状态不变；
4. **通知降级**（REQ-N-004）：主通道失败 3s 内降级，重启后补扫不重复。

| 类型 | 范围 | 负责人 | 工具 | 增量 |

## 3. 测试策略

| 方法 | 用在哪 |
|---|---|
| 等价类划分 | 发布字段（标题长度、图片数量 0–5、核验问题 1–3）、检索参数组合 |
| 边界值 | 信用分 40 / 60 阈值、交接码 72h、发布 60 天过期、输错 5 次锁定、分页 limit 50、单图 2MB |
| 异常路径优先 | 并发提交、重复核销、码过期、上传失败、通道不可用、越权、服务重启 |
| 状态迁移覆盖 | 4 张状态图的每条迁移各一条用例（合法 + 非法） |
| 故障注入 | 存储抛异常、通知适配器抛异常、数据库唯一约束冲突 |

## 4. 覆盖率目标

| 模块 | 目标 | 理由 |
|---|---|---|
| `services/state_machine.py` | ≥90% | 全部迁移组合都是纯函数，没有理由不覆盖 |
| `services/claims.py` | ≥85% | 终审事务与交接码是核心风险点 |
| `services/visibility.py` | ≥90% | 脱敏漏一个分支就是合规事故 |
| `services/notify.py` | ≥80% | 降级链与幂等 |
| 整体 | ≥70% | 低于 70% 不允许发布 |

> 覆盖率数字必须可复现：测试报告里附 `pytest --cov=app --cov-report=term-missing` 的输出。

## 5. 测试环境

| 项 | 内容 |
|---|---|
| 本地 | SQLite（WAL）+ 本地磁盘存储 + ConsoleNotifier |
| CI | GitHub Actions：`ruff check .` + `pytest -q`，PR 必跑 |
| 部署 | 预发布环境（PostgreSQL + MinIO），用于验收与非功能测试 |

## 6. 缺陷管理

- 缺陷一律建 Issue，标签 `type:bug`，标注严重程度 S1–S4 与领域
- 闭环：新建 → 修复 → 回归 → 关闭；回归必须引用原缺陷 Issue
- 测试报告统计：发现数、修复数、遗留数、按严重程度分布
